# 小型文本编辑器开发技术路线图

**作者**：Manus AI
**日期**：2026-04-23

基于 Nebula 当前架构与能力边界，开发一个真正可用的小型文本编辑器（Text Editor）是一项系统工程。本文档详细梳理了 Nebula 当前已具备的基础能力，并系统规划了实现小型文本编辑器所需的缺失原语及阶段演进路线。

## 1. 现状评估：Nebula 当前的文本能力边界

截至 **Phase 3.3.5**，Nebula 在文本渲染与内存管理方面已经打下了坚实的高性能基础，但其本质仍然是一个**只读的文本渲染引擎**。

### 已具备的核心能力
*   **高质量 SDF 渲染**：基于 `stb_truetype` 的预处理图集与 `fwidth` 抗锯齿，支持无极缩放的高清字符渲染。
*   **动态网格重建**：`text_runtime.nelua` 能够在运行时将不可变的 C 字符串（`cstring`）解析并重建成包含位置与 UV 坐标的四边形顶点网格 [1]。
*   **零 GC 内存管理**：Phase 3.3 引入的 `Frame Arena` 允许每帧进行高效的线性内存分配，这为处理大规模文本行或动态排版数据提供了理想的底层设施 [2]。
*   **基础输入抽象**：`app.nelua` 提供了一个统一的输入状态结构（`NebulaInputState`），但目前仅包含鼠标位置与左键点击状态 [3]。

### 缺失的关键能力
当前的 Nebula **无法**支持文本编辑，因为缺失以下三大核心支柱：
1.  **可变文本数据结构**：当前使用不可变的连续内存字符串，每次修改都会导致 O(N) 的重建开销，无法支撑实时插入与删除。
2.  **键盘事件系统**：输入层完全没有键盘按键、修饰键（Ctrl/Shift）、文本字符输入（Text Input Callback）以及操作系统输入法（IME）的接入 [3]。
3.  **光标与选区模型**：渲染层只知道如何画字，完全没有光标（Caret）定位、闪烁逻辑、选区（Selection）范围高亮以及鼠标到字符索引的命中测试（Hit-testing）机制 [1]。

## 2. 核心能力需求清单

要构建一个小型文本编辑器，必须在架构中补齐以下原语。

### 2.1 数据层：可变文本缓冲区 (Mutable Text Buffer)
文本编辑器不能使用简单的字符串拼接来处理用户输入。必须引入专门的数据结构来保证光标位置的 O(1) 插入/删除性能。
*   **Gap Buffer**：最适合小型编辑器的结构，将文本分为光标前和光标后两段，中间留有空白（Gap），在光标附近输入时性能极高。
*   **Rope 或 Piece Table**：适用于超大文件（如几十 MB 的日志），但对于小型编辑器而言可能存在过度设计（Over-engineering）。

### 2.2 交互层：键盘焦点与输入法系统
*   **键盘事件流**：扩展 `NebulaInputState`，接入 GLFW 的 `glfwSetKeyCallback`（处理退格、方向键、回车等控制键）和 `glfwSetCharCallback`（处理实际的 Unicode 字符输入）。
*   **焦点链流转**：建立全局的焦点管理器，确保键盘事件只派发给当前处于激活状态的 `TextVisual` 组件。
*   **IME 基础支持**：对于非英语用户，必须支持操作系统级别的输入法预编辑（Pre-edit）状态显示。

### 2.3 渲染与排版层：光标、选区与排版解耦
*   **排版引擎解耦**：将当前的“字符串到顶点网格”的单体逻辑，拆分为“排版（Shaping/Layout）”和“渲染（Rendering）”两个独立阶段。排版阶段需要计算出每个字符的精确屏幕坐标矩阵。
*   **光标定位与渲染**：根据排版矩阵和当前光标索引，计算光标的 X/Y 坐标，并引入一个独立的闪烁定时器。
*   **命中测试 (Hit-testing)**：实现从屏幕坐标 (X, Y) 反向映射到文本字符串索引 (Index) 的算法，以支持鼠标点击定位光标和拖拽框选。

## 3. 阶段规划：Phase 3.4 演进路线

根据《行业标杆研究与 Nebula 架构演进设想》的规划 [2]，支持文本编辑器所需的能力将被集中放置在即将到来的 **Phase 3.4** 中。以下是详细的子阶段实施路径：

| 子阶段 | 核心目标 | 交付物与关键技术 |
| :--- | :--- | :--- |
| **Phase 3.4.1** | **键盘输入与焦点系统** | 扩展 `app.nelua`，接入 GLFW 键盘回调；在 `interaction_factory.lua` 中完善焦点树流转逻辑，确保组件能正确接收按键事件。 |
| **Phase 3.4.2** | **可变文本缓冲区 (Gap Buffer)** | 实现纯 Nelua 编写的 `GapBuffer` 数据结构，提供 `insert`、`delete`、`move_cursor` 等 O(1) 接口，替换现有的 `cstring`。 |
| **Phase 3.4.3** | **光标渲染与排版解耦** | 重构 `text_runtime.nelua`，分离排版与渲染；新增 `CaretVisual` 负责光标闪烁与定位渲染。 |
| **Phase 3.4.4** | **命中测试与选区高亮** | 实现基于字符包围盒的二分查找命中测试；扩展 SDF 着色器以支持选区背景色高亮（Selection Highlight）。 |
| **Phase 3.4.5** | **小型编辑器 Demo** | 编写 `editor_demo.nelua`，展示一个支持多行输入、退格删除、方向键移动、鼠标定位的完整文本编辑器。 |

## 4. 结论

目前 Nebula（Phase 3.3.5）尚处于只读渲染阶段，**必须完整实现 Phase 3.4** 才能支持开发小型文本编辑器。

由于 Nebula 坚持“零运行时开销”和“编译期推导”的哲学，Phase 3.4 的核心挑战在于如何将动态的 Gap Buffer 内存分配与现有的 Frame Arena 优雅结合，以及如何通过编译期宏生成高效的排版与命中测试代码。这将是 Nebula 迈向真正生产力工具框架的关键一跃。
