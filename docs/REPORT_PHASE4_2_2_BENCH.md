### Methodology

- **Per-instance uniform size**: 64 bytes (std140 layout: pos/size Vec2, bg_color/Border_color Color, border_width, viewport)
- **Instance layout**: 100-column grid, 90% cell fill ratio
- **Warmup**: 3 frames (discard)
- **Measurement**: 60 frames, glfwGetTime wall-clock
- **Rendering path**: App + legacy Slot API → standard_instanced → wgpuRenderPassEncoderDraw(pass, 6, N, 0, 0)
- **Buffer type**: WGPUBufferUsage_Storage (Storage Buffer, not Uniform Buffer)

### Acceptance Criteria (from PLAN_PHASE4_2_3_CJK §2.4)

- **PASSED** (benchmark DISMISSED): 10K frame time degradation < 20% vs 1K baseline
- **FAILED** (benchmark SUSTAINED): 10K frame time degradation ≥ 20% → migration to RGBA32Float texture needed

## Technical Notes

### Derive Type Visibility

**Problem**: Nelua's `aster.parse` + `inject_statement` from user `##[[...]]` blocks cannot
reference types generated by `nebula_derive()` in a separate `##[[...]]` block.

**Solution**: In the user's `##[[...]]` block, re-inject the Uniforms record source via
`nebula_gen_uniform_layout().nelua_record_source` before injecting code that references
the type. Both injections happen in the same `##[[...]]` block, so the Nelua analyzer
resolves the type correctly.

This is the first user-space code to directly reference a derive-generated type name.

### Uniform Layout (64 bytes)

```
offset  field           type      size
0       pos             Vec2      8
8       size            Vec2      8
16      bg_color        Color     16
32      border_color    Color     16
48      border_width    float32   4
52      _pad0           float32   4
56      viewport        Vec2      8
                       TOTAL:    64 bytes
```
